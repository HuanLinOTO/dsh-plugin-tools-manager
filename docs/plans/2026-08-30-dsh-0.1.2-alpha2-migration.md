## 结论 —— ⚠️ 需适配（仅 1 处必改，2 行）

alpha.2 唯一触及本插件的破坏点是 **`@deepseek-ai/dsh-settings` 删除了 `settingsNamespace()` 导出**（`src/settings.ts:19,24` 直接引用，不修则 typecheck 报错、运行时加载即崩）。改为字面量常量 `'tools-manager'`（对齐 alpha2 上游新惯例）即可。其余 dsh 面——`dsh-tools`（schemas/guard/tools/change）、`system-prompt/assemble`、`webServer.register`、cordis `internal/*` 事件、ui-slots/ui-settings 的 `settings.section` 契约、ui-primitives 组件、`window.__ModuleLoader__` 加载契约——在 alpha.2 全部原样保留，**无需任何改动**。vendor cordis/schemastery 代码零变更（仅版本行）。

## 迁移步骤

**需要改动的只有 1 个文件（2 行）**；其余文件（`registry.ts`、`policy.ts`、`gateway.ts`、`config.ts`、`src/client/*`、`cordis.patch.yml`、`scripts/build-client.mjs`、`tests/*`、`vitest.config.ts`）**均无需改动**。

### 0. 前置：先升级 dsh 本体（人类执行）

按 `AGENTS.md` 的「更新 DSH 源码 checkout」SOP：`git pull --ff-only` 到 alpha.2 → `pnpm install --prefer-offive` → `pnpm run build`（≥600s 前台）。插件的 typecheck（tsconfig paths）与 loader.e2e 都解析 `~/.dsh/source/current`，这步不做，插件侧 typecheck 必然失败。

### 1. 必改：`src/settings.ts` 适配 dsh-settings 移除 `settingsNamespace()`

alpha2 将命名空间校验移到 `SettingsProvider.register/update` 的类型参数（`SettingsNamespaceInput` 模板字面量），删除了运行时 helper。上游自身已改为裸字面量（如 `packages/client/ui-chat/src/chat-settings.ts:6`：`export const CHAT_SETTINGS_NAMESPACE = 'ui-chat'`）。照做：

```diff
--- a/src/settings.ts
+++ b/src/settings.ts
@@
-import { settingsNamespace, type SettingsScope } from '@deepseek-ai/dsh-settings'
+import type { SettingsScope } from '@deepseek-ai/dsh-settings'
@@
 /** Settings namespace under which the disabled-tool list persists. */
-export const SETTINGS_NAMESPACE = settingsNamespace('tools-manager')
+export const SETTINGS_NAMESPACE = 'tools-manager'
```

- `'tools-manager'` 通过 alpha2 的类型层校验（小写字母开头 + `[a-z0-9-]`），运行时 `parseSettingsNamespace` 同样放行（正则未变 `/^[a-z][a-z0-9-]*$/`）。
- `sctx.settings.register(SETTINGS_NAMESPACE, Config, { base: entry as never })`（`settings.ts:65`）与 `settings.update(SETTINGS_NAMESPACE, ...)`（`gateway.ts:148`）在 alpha2 新签名 `register<const Namespace extends string, T>(ns: Namespace & SettingsNamespaceInput<Namespace>, ...)` / `update<const Namespace extends string>(...)` 下**直接通过，无需改动**（const 字面量类型）。
- 「already registered」去重 catch（`settings.ts:69`）无需改动：alpha2 错误消息仍含 `already registered`。
- `scope.get()` / `scope.watch()` 语义不变，`ToolsManagerSettingsBridge` 整体无需动。

**可选简化（非必须）**：alpha2 新增 `SettingsProvider.installSection(owner, ns, schema, entry, hooks)`，与 `settings.ts` 手写的「register + provider 失效回退 + watch 通知」桥接逻辑一一对应，可改用之删掉约 20 行手写桥接。不改也完全正常工作。

### 2. 建议（非必须）：`package.json` peer 版本对齐

`peerDependencies` 中 8 个 `@deepseek-ai/dsh-*` 由 `^0.1.2-alpha.1` → `^0.1.2-alpha.2`（semver 上不升也满足，升了表达已对 alpha2 验证）；`@deepseek-ai/cordis` `^4.0.1` 可不动（4.0.2 满足）或一并对齐。注意本插件**没有** `link:`/`overrides` 指向 `source/current`——`tsconfig.json` 的 5 条 paths 只是 typecheck 解析，无运行时耦合，升级后这些 `.d.ts` 随 dsh 重构自动变为 alpha2 版本，已核对无类型面破坏（cordis/schemastery/webserver 零 diff，system-prompt 的 `PromptAssembly` 未变）。
