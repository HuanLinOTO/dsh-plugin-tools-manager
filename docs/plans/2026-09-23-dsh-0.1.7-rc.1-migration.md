- **RC1-04 命中**：`src/settings.ts` 原用 `sctx.settings.register(SETTINGS_NAMESPACE, Config, { base: entry })` 建用户层并 `scope.watch` 热更新。0.1.7 删除 `register`：改为 (a) `config.ts` 的 `disabled` 字段标 `.volatile()`，schema 用 **`@deepseek-ai/schemastery`** 构造（3.18.4 起才有 `.volatile()`），(b) `apply` 收到 `EntryConfig`（`disabled: Volatile<string[]>`），(c) `settings.ts` 在 `ctx.inject(['settings'], …)` 里 `configure({ auto: false }, ctx.fiber)` 声明「自带设置页」，(d) bridge 的 `source()` 每次 `entry.disabled.get()` 读取实时值（Loader 原地更新引用，无需 remount 或 watcher）。值持久化到 profile `cordis.patch.yml` 的 `tools-manager` entry 下（旧 `settings.yaml` 段由上游一次性导入）。
- **RC1-01 命中**：9 个 `@deepseek-ai/dsh-*` peer `^0.1.5-rc.1` → `^0.1.7-rc.1`；`@deepseek-ai/cordis` 保持 `^4.0.1`。
- **RC1-26 命中**：`IconChevronRightOutline14` → `IconChevronRightOutlineMedium`（`size={14}` 仍有效，`size` prop 现控尺寸；`Regular`=1px / `Medium`=1.3px 描边）。
- **RC1-27 非命中**：客户端面板是自绘 `settings.section` 页 + 自建 HTTP 通道，不经 `settingsScope`；0.1.7 的 `settings.section` slot（`kind:'list'`,`scope:'root'`）仍存在，注册形状不变。
- **RC1-31 非命中**：插件用 `settings.section`（仍存在），未用被退役的 `settings.plugin.item`；`pluginManager` Remote 为可选新增。
- **gateway 的 `settings.update` 无需改**：0.1.5 的 provider 与 0.1.7 的 `SettingsForms` 均提供 `update(ns, patch)`；语义等价（0.1.7 第三参 `expectedRevision` 可选）。测试固化了「update 后 bridge 仍返回旧值」的既有行为，故保持 `buildView(registry, bridge)` 不动。

## 行动

1. **RC1-01**：peer 提升（9 处）。
2. **RC1-04**：
   - `src/config.ts`：`import z from '@deepseek-ai/schemastery'`；新增 `Volatile` 类型与 `EntryConfig`；`disabled` 标 `.volatile()`；`Config` 断言为 `z<EntryConfig>`；`Config.disabled` 放宽为 `readonly string[]`。
   - `src/settings.ts`：删除 `settings.register`/`SettingsScope`/`isUnloading`/watcher；新增 `configure({ auto: false }, ctx.fiber)`；`source()` 读 `entry.disabled.get()`。
   - `src/index.ts`：`apply(ctx, config: EntryConfig)`；重导出 `EntryConfig`。
   - `package.json`：移除 peer `schemastery`，新增 peer/meta/dev `@deepseek-ai/schemastery: ^3.18.4`（沿用 `dsh-plugin-sidebar-brand-text` 的既有 0.1.7 迁移范式）。
3. **RC1-26**：`ToolsManagerPanel.tsx` 图标改名（import + JSX 两处）。

## 实际结果（2026-09-23 执行记录）

- **registry 0.1.7 静态校验**：host + client 合面 `tsc` **零错误**。
- **测试**：`pnpm test` 4 文件 / 45 用例 **全绿**。
- **构建**：以 registry paths 跑 `tsc -p tsconfig.build.rc1.json` + `build-client.mjs` ✅，`lib/{index,config,settings}.js` + `lib/client.js` 重建（client bundle 以 `__ModuleLoader__.load` 包裹，图标已为 `IconChevronRightOutlineMedium`）。
- **对当前 checkout 的 `pnpm typecheck`**：**红 3 处**（过渡态，checkout 升级到 0.1.7 后消失）：
  - `src/config.ts(18,15): Module '"@deepseek-ai/cordis"' has no exported member 'Volatile'`
  - `src/config.ts(47,45): Property 'volatile' does not exist on type 'Schema<...>'`
  - `src/settings.ts(51,37): Property 'configure' does not exist on type 'SettingsProvider'`
  这是版本跳变的预期差异（本地类型源仍是 0.1.5-rc.2 的 vendor），非逻辑回归；`@deepseek-ai/cordis` 4.0.4 / `@deepseek-ai/schemastery` 3.18.4 的 registry 校验已证 0.1.7 下正确。
- **依赖/锁文件**：`package.json` peer 面变更导致本地 `pnpm install` 拉入 `@deepseek-ai/schemastery@3.18.4`（+ cosmokit）并写入 `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude`；`pnpm-lock.yaml` 与 `pnpm-workspace.yaml` 在本仓库被 `.gitignore` 排除（dev-only，profile 自带），不随发布；无旧 cohort 残留。bare `schemastery` 保留在 devDependencies（无用但无害，`dsh-plugin-sidebar-brand-text` 同款）。
- **改动文件**：`src/config.ts`、`src/settings.ts`、`src/index.ts`、`src/client/ToolsManagerPanel.tsx`、`package.json` + 预构建 `lib/`。工作区 link 路径未变；未提交。

## pending / 残余风险

- **运行时未在真实 0.1.7 host 冒烟**：需验证 (a) `@deepseek-ai/schemastery` 在 profile 运行时能解析（与 `dsh-plugin-sidebar-brand-text` 同款依赖面，但该插件是否已在实机验证待确认）；(b) settings 面板写路径 `settings.update('tools-manager', { disabled })` 在 0.1.7 的 volatile 校验下接受该 patch；(c) `configure({ auto: false })` 抑制自动页后，自绘 `settings.section` 页仍正常挂载。
- **`disable` 语义跨边界**：`handleSet` 返回的 tree 仍按 update 前的 bridge 读取（测试固化），实机表现为「切换后需下一次 `/list` 才刷新」——与 0.1.5 行为一致；若 0.1.7 的 Live update 时序改变，需复核。
- client 面未参与 `pnpm typecheck`（构建走 esbuild）；已用临时 client tsconfig 对 registry 0.1.7 校验通过。
